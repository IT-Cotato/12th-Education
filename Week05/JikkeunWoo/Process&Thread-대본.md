# 공부 자료

## 1. 프로세스 (Process)

- 정의: 실행 중인 프로그램의 인스턴스다.
    - 바탕화면의 `Chrome.exe` 파일 자체는 프로그램이다.
    - 이 파일을 더블 클릭하여 메모리에 로드되고 CPU에 의해 실행되는 순간, 프로세스가 된다.
- 핵심: 자원 할당의 단위 (Unit of Resource)
    - 운영체제(OS)는 새로운 프로세스가 생성될 때마다 독립된 메모리 공간을 할당한다. (Code, Data, Heap, Stack)
- 특징: 격리 (Isolation)
    - OS는 각 프로세스가 자신만의 메모리 영역을 갖도록 철저히 격리한다.
    - 이유: 안정성. A 프로세스(크롬)에 오류가 발생해 비정상 종료되어도, B 프로세스(파워포인트)는 영향을 받지 않는다. 만약 메모리를 공유한다면, A의 오류가 B의 데이터를 덮어써서 시스템 전체가 불안정해질 것이다.

## 2. 스레드 (Thread)

- 정의: 프로세스라는 작업 환경 내에서, 실제로 일을 하는 일꾼(실행 흐름)이다.
- 핵심: 실행의 단위 (Unit of Execution)
    - 프로세스가 자원을 할당받는 집(환경)이라면, 스레드는 그 집 안에서 실제 작업을 수행하는 사람이다.
    - 모든 프로세스는 최소 1개 이상의 스레드(메인 스레드)를 가진다.
- 특징: 공유 (Sharing)
    - 하나의 프로세스 내에 있는 스레드들은, 그 프로세스의 자원(메모리)을 공유한다.
    - 경제성: 이 공유 덕분에, 새로운 프로세스를 만드는 것(새 집 짓기)보다 새 스레드를 만드는 것(새 일꾼 고용)이 훨씬 자원이 적게 들고 빠르다.

## 3. 프로세스와 스레드의 메모리 구조

하나의 프로세스(예: 크롬) 안의 메모리 구조다.

- Code 영역: 실행할 코드(프로그램)가 저장된다.
    - ➔ 모든 스레드가 공유 (같은 매뉴얼을 보고 일함)
- Data 영역: 전역 변수, 정적 변수가 저장된다.
    - ➔ 모든 스레드가 공유 (가게의 오늘의 공지사항)
- Heap 영역: 동적으로 할당되는 데이터(객체, 인스턴스)가 저장된다.
    - ➔ 모든 스레드가 공유 (가게의 공용 냉장고)
- Stack 영역: 함수 호출 시 사용되는 지역 변수, 매개변수가 저장된다.
    - ➔ 각 스레드마다 독립적으로 할당 (일꾼의 개인 작업 수첩)

### Q. 왜 스레드는 Stack을 독립적으로 가지는가?

- Stack은 함수의 작업 공간이다.
- 만약 T1(스레드 A)이 `calculate_A()` 함수를 실행하고 T2(스레드 B)가 `calculate_B()` 함수를 동시에 실행할 때 Stack을 공유한다면, 두 함수의 지역 변수(A의 `local_A`, B의 `local_B`)가 서로 섞여 엉망이 된다.
- 따라서, 스레드가 독립적인 실행 흐름을 가지려면, 자신만의 작업 수첩(Stack)은 반드시 따로 가져야 한다.

### Q. 왜 스레드는 Heap을 공유하는가?

- 협업을 위해서다. T1(스레드 A)이 서버에서 받아온 뉴스 데이터(Heap에 저장)를 T2(스레드 B)가 화면에 그려야 한다.
- 공용 냉장고(Heap)에 데이터를 넣어두지 않으면, 스레드 간의 데이터 전달이 매우 비효율적이 된다.
- 하지만 이 공유 때문에 다음 문제가 발생한다.

## 4. 싱글 스레드 vs 멀티 스레드

### 4.1. 싱글 스레드의 한계: 블로킹 I/O (Blocking I/O)

- 대부분의 UI 프로그램(웹 브라우저, 모바일 앱)은 사용자의 입력을 처리하는 '메인 스레드'가 하나(싱글 스레드)다.
- 블로킹 I/O는 네트워크 요청이나 파일 읽기처럼 오래 걸리는 작업을 호출했을 때, 그 작업이 끝날 때까지 스레드 전체가 멈추는(Blocked) 현상이다.
- 문제점: 메인 스레드(일꾼 1명)가 오래 걸리는 작업(예: 10초짜리 다운로드)에 붙잡혀 멈추면, 그동안 사용자의 다른 클릭이나 스크롤 입력을 전혀 처리하지 못한다. 이것이 '앱 멈춤(Freeze)' 현상이다.

```python
# 예시 - 싱글 스레드의 블로킹 작업
import time

def on_download_button_click():
    print("다운로드를 시작합니다...")
    
    # 이 작업이 10초간 메인 스레드 전체를 멈추게 함
    # (네트워크에서 데이터를 동기(sync)로 가져옴)
    time.sleep(10) # 10초 걸리는 작업이라 가정
    
    # 10초 뒤에야 이 코드가 실행됨
    print("다운로드 완료!")

# 메인 스레드가 이 함수를 실행하면,
# 10초 동안 다른 어떤 일(예: 사용자 클릭)도 처리하지 못하고 멈춘다.
```

- **해결책:** 이 문제를 해결하고 앱의 '응답성'을 높이기 위해, 오래 걸리는 작업은 별도의 스레드(워커 스레드)에 맡기는 '멀티 스레딩'을 사용한다.

### 4.2. 멀티 스레드의 문제점: 경쟁 상태 (Race Condition)

- 정의: 멀티 스레딩 환경에서, 여러 스레드가 '공유 자원(예: Heap 영역의 변수)'에 동시에 접근(특히 '쓰기')하려 할 때 발생하는 문제다.
- 문제 예시: '좋아요' 기능을 예로 들어보자.
    - 공유 자원: `total_likes = 0` (Heap 영역에 저장된 전역 변수)
    - 스레드 A와 스레드 B가 동시에 좋아요 버튼을 눌렀다고 가정한다. (결과는 2가 되어야 함)

```python
# Python 코드 (threading 모듈)
import threading
import time

total_likes = 0 # 공유 자원 (Heap에 저장)

def increment_likes():
    global total_likes # 전역 변수에 접근

    # 스레드 A: total_likes = 0 읽음
    # (이때 OS가 A를 멈추고 B에게 CPU를 넘길 수 있음)

    current_likes = total_likes 
    time.sleep(0.001) # 짧은 시간 지연 (경쟁 상태 발생 확률 높임)
    total_likes = current_likes + 1
    # 스레드 A: total_likes = 1로 씀 (하지만, B도 0을 읽었다면?!)

# 스레드 생성 (일꾼 2명)
thread1 = threading.Thread(target=increment_likes)
thread2 = threading.Thread(target=increment_likes)

# 좋아요 2개 누르기 시뮬레이션
thread1.start()
thread2.start()

thread1.join() # 스레드 종료 대기
thread2.join()

print(f"최종 좋아요 개수: {total_likes}")
# 예상 결과: 2 (하지만 1이 출력될 가능성이 높음)
```

- 결과: 2명이 눌렀는데도 `total_likes`는 2가 아닌 1이 될 수 있다. 데이터가 유실(손실)되었다.
- 이것이 바로 실행 '순서(경쟁)'에 따라 결과가 달라지는 '경쟁 상태'다.
- 해결책 (개념만):
    - 이런 문제를 막기 위해 '동기화(Synchronization)'가 필요하다.
    - `Mutex`나 `Semaphore` 같은 '자물쇠(Lock)'를 사용해, 한 스레드가 `total_likes`를 읽고 쓰는 동안 다른 스레드가 접근하지 못하도록 막아야 한다.
