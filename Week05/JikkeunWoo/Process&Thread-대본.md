`#9` 공유 영역 vs 독립 영역

- **공유 영역 (Shared)에는, 코드, 데이터, 힙이 있습니다.**
    - `Code` 에는,  컴파일된 기계어 코드를 저장합니다.
    - `Data` 에는, 전역, 정적 변수 등을 저장합니다.
    
             데이터는 시작할때 초기화해서, 프로세스 종료까지 유지합니다.
    
    - **`Heap`** 에는, 실행 중 동적할당된 변수를 저장합니다.
- **독립 영역 (Independent):**
    - **`Stack`** 은 ,함수 실행 중 지역변수를 저장하는 임시 공간으로, 지역,매개변수, 리턴값 등을 저장합니다.

`#10`Q. 왜 Stack은 독립해야 할까?

그럼 여기서 왜 stack은 독립해야하는지를 알아보겠습니다.
Stack은 '함수의 작업 공간'인데요. 이 코드를 보시면
일꾼 A(T1)가 `calculate_A()` 함수를 실행하고, 일꾼 B(T2)가 `calculate_B()` 함수를 실행한다고 해보겠습니다.

```jsx
**// T1(일꾼1)이 실행하는 함수
function calculate_A(value) {
    let local_A = value + 10; // T1의 Stack에 저장
}

// T2(일꾼2)가 실행하는 함수
function calculate_B(text) {
    let local_B = text.length; // T2의 Stack에 저장
}**
```

만약 Stack을 공유한다면, A의 `local_A`와 B의 `local_B` 변수가 서로 섞여 엉망이 되겠죠?
따라서, 스레드가 '독립적인 실행 흐름'을 가지려면, **Stack은 반드시 각 스레드마다 '독립적'이어야 합니다.**

`#11` **Q. 왜 Heap은 공유할까?**

여러 번 동작하는 코드를 효율적으로 실행하려면 공유되어야할거고, 

데이터도 전역 변수를 저장하니까 공유되어야할거같은데, 

동작할당을 하는  heap이 좀 생소하실 수도 있을거 같은데요.

다음은 heap 영역이 왜 공유되는지에 대해 알아보겠습니다.  

- 바로 '협업'을 위해서입니다. 이 코드를 보시면
일꾼 A(T1)가 Heap에 '뉴스 데이터'를 가져다 놓으면,
일꾼 B(T2)가 그 데이터를 꺼내서 '화면'에 그려 내야 합니다.

```jsx
// Heap에 저장된 '공유 데이터'
shared_news_list = [ "뉴스A", "뉴스B" ]

// T1(일꾼1)이 새 뉴스를 추가
function add_News(news) {
    shared_news_list.append(news); // Heap 데이터 수정
}

// T2(일꾼2)가 뉴스를 읽음
function get_News_Count() {
    return shared_news_list.length; // Heap 데이터 읽기
}
```

이 '공유' 덕분에 스레드들은 효율적으로 협업할 수 있습니다.
하지만 만약, 공유하다 문제가 발생한다면 어떻게 해야할까요?

`#12`  싱글 스레드, 멀티 스레드란 ?

이를 이해하기 위해, 우선 스레드의 종류에 대해 좀 더 알아보겠습니다. 

스레드는 크게 싱글스레드와 멀티스레드로 나눌 수 있습니다.     

싱글 스레드란, 프로세스가 스레드라는 ‘작업 경로’를 하나만 가지는 방식입니다.

따라서, 한 번에 하나의 작업만, 순차적으로 처리할 수 있습니다.

멀티 스레드란, 프로세스에 여러 개의 스레드를 동시에 실행하는 것처럼 보이게 하는 방식인데요,   

여러 스레드가 프로세스의 자원을 공유하면서 각자 다른작업을 처리합니다. 

동시에 실행하는 것 처럼 보인다고 한 이유는 , cpu가 여러 개인 경우에만 동시에 실행할 수 있고,

cpu가 1개인 경우에는 빠르게 왔다갔다하면서 동시에 실행하는 것 처럼 보이게 하기 때문입니다.

`#13` 싱글 스레드의 한계  문제 코드 (Python)

다시 돌아와서, 스레드가 자원을 공유하다 문제가 발생하는 경우에 대해 알아볼 건데요, 
스레드가 1개인 싱글 스레드부터 보겠습니다.

일꾼이 한 명뿐인 스레드의 가장 큰 문제는 **블로킹 I/O**입니다.
블로킹 I/O는 네트워크 요청처럼 오래 걸리는 작업을 할 때, 

그 작업이 끝날 때까지 스레드 전체가 멈추는 현상을 말합니다.

이 코드를 같이 보겠습니다.

```python
import time

def on_download_button_click():
    print("다운로드를 시작합니다...")
    
    # 이 작업이 10초간 메인 스레드 전체를 멈추게 함
    time.sleep(10) # 10초 걸리는 네트워크 작업이라 가정
    
    # 10초 뒤에야 이 코드가 실행됨
    print("다운로드 완료!")

# 메인 스레드가 이 함수를 실행하면,
# 10초 동안 다른 어떤 일(예: 사용자 클릭)도 처리하지 못하고 멈춥니다.
```

다운로드로 인해 메인 스레드가 10초간 멈추면, 사용자는 앱이 얼어붙었다고 느끼게 됩니다. 

이 문제를 해결하고 앱의 응답성을 높이기 위해, 우리는 여러 개의 스레드라는 

일꾼을 더 추가해 멀티 스레드를 사용합니다.

`#15`문제 예시: 경쟁 상태 (Race Condition)

이러한 경우를 경쟁상태라고 합니다.
이 코드는 스레드 a,b가 각각 좋아요를 눌러, 총 2개가 되는 상황입니다.

공유 자원은, `total_likes` 이고, 현재 공유 자원인 Heap에 있는 상황입니다.
스레드 A와 B가 동시에 좋아요를 눌렀다 하더라도, 결과는 2가 되어야합니다.

`increment_likes` 함수 안에서, `total_likes`를 읽고, 1을 더한 뒤, 다시 쓰는 작업을 합니다.

```python
import threading
import time

total_likes = 0 # 공유 자원 (Heap)

def increment_likes():
    global total_likes
    
    current_likes = total_likes # 1. 읽기 (B: 0 읽음)
    
    time.sleep(0.001) 
    
    total_likes = current_likes + 1 # 2. 쓰기 (B: 1 씀)

# ... (스레드 2개 생성 및 실행) ...
print(f"최종 좋아요 개수: {total_likes}")
```

이런 식으로, 경쟁상태가 발생가능한 공유자원 접근 코드영역을 임계구역 이라고 합니다. (주로 스레드가 공유자원을 수정하려는 경우 발생합니다.)

`#16`Race Condition 결과

처리 과정 및 결과는 다음과 같은데요,

스레드 A가 0을 읽고, CPU가 스레드 B로 넘어가서 B도 0을 읽을 수 있습니다.
그럼 둘 다 1을 더해서 최종 결과를 각각 1로, 2번 덮어쓰게 되죠.

이것이 바로 여러 스레드가 하나의 공용 자원을 동시에 건드려서, 결과가 망가지는 경쟁 상태입니다.

`#35`**퀴즈 8 답**
정답은 B, 블로킹 I/O입니다. 대본 #13에서 설명했듯이, 오래 걸리는 작업으로 인해 전체 스레드가 멈추는 현상을 블로킹 I/O라고 합니다.

**A. 경쟁 상태 (Race Condition):** 오답입니다. 이는 '멀티 스레드' 환경에서 공유 자원 접근 시 '데이터가 유실'되는 문제입니다.

**D. Context Switching (문맥 교환):** 오답입니다.  문맥 교환은 OS가 스레드를 빠르게 전환하며 '동시에 실행하는 것처럼' 보이게 하는 '기술'을 의미하며, 문제 현상 자체가 아닙니다.
