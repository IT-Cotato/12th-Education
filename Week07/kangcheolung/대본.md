# 대본

안녕하세요 이번 CS 교육을 맡게된 백엔드 12기 강철웅입니다.  이번 교육 주제는 HTTP입니다. 

---

교육 목표를 먼저 보자면 첫번째로 HTTP의 특징, HTTP 메서드와 상태 코드, HTTP 주요 헤더 순으로 알아볼 예정입니다. 

---

교육에 들어가기 전에 먼저 HTTP가 무엇인지부터 알아보겠습니다. 
HTTP(HyperText Transfer Protocol)란 웹 브라우저와 웹 서버가 데이터를 주고받기 위해 사용하는 통신 규약(프로토콜)으로, HTML 문서와 같은 웹 리소스들을 전송하는 데 기본적으로 사용되며, 요청(Request)과 응답(Response) 구조로 이루어져 있습니다. 

---

이번에 알아볼 HTTP의 특징은 크게 4가지가 있는데요 HTTP는 요청과 응답을 기반으로 동작하고 미디어 독립적이고, 상태를 유지하지 않고(스테이스리스 프로토콜) 지속 연결을 지원한다는 특징이 있습니다. 이제 하나하나 자세히 알아보겠습니다. 

---

첫 번째로 요청 응답 기반 프로토콜에 대해 확인해보겠습니다. 

사진과 같이 HTTP는 기본적으로 요청 메세지를 보내는 클라이언트와 이에 대한 응답 메세지를 보내는 서버가 서로 HTTP 요청 메세지와 HTTP 응답
메세지를 주고 받는구조인 요청 응답 기반 프로토콜이라는 점입니다. 

---

다음으로 미디어 독립적 프로토콜을 살펴보겠습니다. 

먼저 미디어 타입이란 HTTP에서 메시지로 주고받는 자원의 종류를 뜻합니다. 

그래서 HTTP는 특정 미디어 타입에 종속되지 않기 때문에,HTML, PNG, JSON, XML, PDF 등 다양한 형태의 자원을 동일한 방식으로 송수신할 수 있는 미디어 독립적인 프로토콜입니다. 

---

스테이트리스 프로토콜을 살펴보겠습니다. 

HTTP는 상태를 유지하지 않는 stateless 프로토콜인데요. 즉, 서버는
HTTP 요청을 보낸 클라이언트 관련 상태를 기억하지 않는다는 특징이 있습니다. 

---

마지막 특징인 지속 연결 프로토콜을 확인해보겠습니다. 

HTTP는 지속연결이라는 기술을 제공해줍니다. 이를 다른 표현으로 Keep
Alive라고도 부르는데요. 

그럼 지속연결은 무엇일까요? 

지속연결이란 하나의 TCP 연결 상에서 여러 개의 요청-응답을
주고받을 수 있는 기술입니다. 지속연결은 비지속 연결과 다르게  빠른
속도로 여러 HTTP의 요청과 응답을 처리할 수 있다는 장점이 있습니다. 

---

지금까지 HTTP의 특징에 대해 알아봤는데요. HTTP 메서드와 상태코드를 알아보기 전에 잠깐 정리를 해보겠습니다. 
HTTP는 요청과 응답을 기반으로 하고, 자원의 종류와 무관한 미디어 독립적이며, 클라이언트 상태를 기억하지 않는 Stateless 프로토콜입니다. 그리고 하나의 TCP 연결로 여러 요청을 처리하는 지속연결을 지원합니다. 

---

이제 HTTP 메서드들에 대해 알아보겠습니다. 대부분의 개발자분들이 많이 사용하는 메서드들이 있는데요 여기서 GET/HEAD, PUT/PATCH, POST, DELETE에 대해 알아보겠습니다. 

---

GET은 가장 흔히 사용되는 메서드 중 하나로, 자원을 조회하는
용도의 메서드입니다. 
HEAD도 자원 조회을 위한 메서드지만 GET과 가장 큰 차이점은 오른쪽사진과 같이 응답 메세지에 메세지 본문이 포함되지 않다는 점입니다.

---

사실 저도 HEAD를 사용한적이 없기도하고 대부분의 경우 응답 메시지의 본문이 필요하기 때문에 HTTP 메서드 중에서는 GET을 가장 많이 사용합니다.

그렇다면 HEAD 메서드는 언제 사용할까요?

예를 들어 파일을 다운로드하기 전에 **리소스가 실제로 존재하는지**,

또는 **접근 권한이 있는지**만 미리 확인하고 싶은 경우가 있습니다.

이때 GET을 사용하면 불필요하게 파일 전체를 내려받게 되지만,

HEAD를 사용하면 **헤더 정보만으로 상태 코드와 메타데이터를 확인**할 수 있습니다.

또한 대용량 파일의 경우, HEAD 메서드를 통해 **파일 크기나 타입을 먼저 확인**

한 뒤 실제로 다운로드할지 판단할 수도 있습니다. 

이외에도 캐시 검증이나 서버 상태를 확인할 때도 HEAD 메서드를 사용합니다. 

---

다음으로 PUT과 PATCH를 살펴보겠습니다. 

PUT과 PATCH는 수정한다는 공통점이 있지만, PUT 메서드와 PATCH 메서드와 다른 점은 PUT 메서드는 ‘덮여쓰기’를 요청하는 메서드인 반면에 PATCH 메서드는 ‘부분적 수정’을 요청하는 메서드입니다.

---

마지막으로 POST와 DELETE에 대해 알아보겠습니다. 
POST는 서버로 하여금 특정 작업을 처리하도록 요청하는 용도로
사용되는 메서드인데요. 많은 경우 ‘클라이언트가 서버에 새로운
자원을 생성하고자 할 때’ 사용됩니다.
DELETE 메서드는 특정 자원의 삭제를 요청할 때 사용되는 메서
드입니다.

---

이제 HTTP 상태 코드에 대해 알아보겠습니다. 상태코드는 매우 많은데 이번에는  200번대, 300번대, 400번대, 500번대에 대해 알아보겠습니다. 

---

요청이 성공했으나, 메세지 본문으로 표시할 데이터가 없음을 나타내는 204가 있습니다.

리다이렉션 상태 코드인 300번대를 살펴보면 일단 크게 영구적 리다이렉션인 301과 308이 있고, 일시적 리다이렉션인 302와 303, 307이 있습니다. 

그럼 여기서 영구적/일시적 리다이렉션의 차이점을 살펴보자면

내면 항상 새로운 URL로 리다이렉트됩니다.

그리고 일시적 리다이렉션은 자원의 위치가 임시로 변경되었거나 임시로 사용 할 URL이 필요한 경우에 주로 사용됩니다.

400번대는 클라이언트 에러 상태를 나타냅니다. 하나하나 살펴보자면 

요청 메세지의 내용이나 형식 자체에 문제가 있음을 나타내는 400
요청한 자원에 대한 유효한 인증이 없음을 나타내는 401
자원에 대한 접근 권한이 충분하지 않음을 나타내는 403
요청받은 자원을 찾을 수 없음을 나타내는 404
요청한 메서드를 지원하지 않음 405

![image.png](%EB%8C%80%EB%B3%B8/image%201.png)

여기서 401과 403에 대해 헷갈리면 안되는데요. 

401은 인증을 요구하는 상태 코드이고, 403은 권한(인가)를 요구하는 상태
코드입니다. 여기서 인증이란 ‘자신이 누구인지를 증명하는 작업’을 의미하고, 권한이란 ‘인증된 주체에게 허용된 작업’을 의미합니다.
예를 들어 로그인된 모든 유저는 인증된 유저라고 할 수 있지만(401), 모든 유저가 관리자 페이지에 들어갈 수 없는 것 처럼 인증이 되었더라도 권한이 충분하지 않을 수 있습니다(403).

지금까지 알아본 HTTP 메서드와 상태코드를 정리해보자면 HTTP 메서드에는 자원 조회하는 GET과 HEAD, 자원 수정하는 PUT/PATCH, 자원을 생성하는 POST, 자원을 삭제하는 DELETE가 있습니다. 
그리고 상태코드를 간단하게 보면 요청 정상처리하는 200번대, 리다이렉션과 관련된 300번대, 클라이언트 오류와 서버 에러를 나타내는 400번대와 500번대가 이습니다.

이제 HTTP의 주요헤더를 알아볼 예정인데요. 

크게 

요청 메세지에서 주로 활용되는 HTTP 헤더
응답 메세지에서 주로 활용되는 HTTP 헤더
요청과 응답 메세지 모두에서 활용되는 HTTP 헤더로 구분하여 알아보겠습니다. 

---

요청 메세지에서 주로 활용되는 HTTP 헤더로는 Host, User - Agent, Referer등이 있는데요. 

Host는 요청을 보낼 호스트가 명시되는 헤더로 도메인 네임이나 IP 주소로 표현되며,포트 번호가 포함될 수도 있습니다.

User - Agent 헤더에는 요청 메세지를 보낸 클라이언트의 프로그램과
관련된 정보가 명시됩니다.

마지막으로 Referer 헤더는 클라이언트가 요청을 보낼 때 머무르던 URL이 명시되며, 이를 통해 클라이언트의 유입 경로를 파악할 수 있습니다.

---

응답 메세지에서 주로 활용되는 HTTP 헤더로는 Server, Allow, Locaton이 있습니다. 

Server는 HTTP 응답 메세지를 보내는 서버 호스트와 관련된 정보가 명시됩니다.

Allow 헤더는 처리 가능한 HTTP 헤더 목록을 알리기 위해 사용되고,

Location 헤더는 클라이언트에게 자원의 위치를 알려 주기 위해 사용됩니
다. 주로 리다이렉션이 발생했을 때나 새로운 자원이 생성되었을 때 사용됩니다.

---

요청과 응답 메세지 모두에서 활용되는 HTTP 헤더를 보면 Date, Content-Length, Content-Type, Content-Language, Content-Encoding등이 있ㄴ는데요. 

Date헤더는 메세지가 생성된 날짜와 시각에 관련된 정보를 담는 헤더입니다.

Content-Length헤더는 메세지 본문의 바이트 단위 크기를 표현하기 위해 사용됩니다.

Content-Type은 메세지 본문에서 사용된 미디어 타입을 의미합니다.

퀴즈 7번 

HTTP 메서드 중에서 다음과 같은 상황에서 사용하기에 적절한 메서드는?

- 파일 다운로드 전에 파일이 실제로 존재하는지 리소스 존재 여부만 확인하고 싶다.
- 해당 파일에 접근 권한이 있는지 알고 싶다.
- 대용량 리소스에 접근하기 전에, 상태만 미리 확인하고 싶다.

`답은 HEAD`입니다. 

[해설]

HEAD 메서드는 GET과 동일하게 리소스를 조회하지만, 응답 본문 없이 헤더만 반환한다. 이를 통해 파일 다운로드 없이 존재 여부나 접근 가능 여부 같은 메타데이터만 확인할 때 적절하다.

퀴즈 8번

 다음 중 상태 코드와 그 구문을 짝지은 것으로 올바르지 않은 것은?

1. 200 - OK

2. 307 - Permanent Redirect

1. 400 - Bad Request

4. 404 - Not Found

5. 500 - Internal Server Error

답은 2번입니다. 

상태코드 `307`은 임시 리다이렉트를 의미하는 상태 코드(Temporary Redirect)이며, 요청을 임시로 다른 URI로 전달하되 HTTP 메서드를 유지하는 상태 코드이다. 영구적인 이동을 의미하는 상태 코드는 `308`이므로, 2번은 잘못된 짝이다.

퀴즈 9번

다음 중 http 특징에 대한 설명으로 올바르지 않은 것을 고르시오. 

1. http는 웹 브라우저와 웹 서버가 데이터를 주고 받기위해 사용하는 통신 규약이다. 
2. http는 웹 리소스를 전송하는데 사용된다. 
3. http는 요청과 응답 구조로 이루어져있다.
4. http는 stateless하기 때문에 클라이언트 상태를 저장하지 않는다. 
5. http는 이전 요청을 기억해서 항상 연결을 유지할 수 있다. 

정답은 5번입니다. 

HTTP는 **연결을 유지할 수는 있어도상태를 기억하지는 않기때문에 5번이 틀렸습니다.**

킹킹 문제

HTTP의 ‘미디어 독립성’ 특징으로 인해 클라이언트와 서버가 데이터 형식을 맞추기 위해 사용하는 가장 핵심적인 방법은 무엇인가요?

1 서버가 지원하는 특정 미디어 타입만 강제로 사용하게 한다.

2 TCP 연결을 맺을 때 미리 데이터 타입을 정의한다.

3 Coding-Encoding을 일치시켜 해결한다.

4 Content-Type 헤더를 통해 본문에 담긴 미디어 타입을 명시한다.

정답: 4번  HTTP는 미디어 독립적인 프로토콜이기 때문에 클라이언트와 서버는 전송되는 데이터의 형식을 **사전에 고정하지 않는다**.
