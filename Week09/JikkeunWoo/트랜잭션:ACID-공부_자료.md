# 📚 공부 자료 - 트랜잭션 : ACID

## 1. 트랜잭션(Transaction)의 개요

- **정의:** 데이터베이스의 상태를 변화시키는 **논리적인 작업의 단위**입니다. 물리적으로는 여러 개의 SQL 명령(Insert, Update 등)으로 이루어져 있어도, 논리적으로는 쪼개질 수 없는 하나의 작업으로 취급합니다.
- **필요성:** '계좌 이체'와 같이 입금과 출금이 동시에 이루어져야 하는 상황에서, 데이터의 정합성을 보장하기 위해 필수적입니다. 중간에 서버가 다운되더라도 돈이 증발하는(데이터 불일치) 사고를 막아줍니다.
- **핵심 원칙:** **All or Nothing** (전부 실행되거나, 아예 실행되지 않아야 함).

## 2. 트랜잭션 제어 (TCL)

트랜잭션을 제어하는 명령어입니다.

- **Commit (커밋):** 트랜잭션 내의 모든 작업이 성공적으로 수행되었을 때, 변경 사항을 데이터베이스에 **영구적으로 반영**하는 명령어입니다.
- **Rollback (롤백):** 작업 중 하나라도 실패하거나 에러가 발생했을 때, 트랜잭션 시작 전의 상태로 작업을 **되돌리는(취소)** 명령어입니다.

## 3. ACID : 트랜잭션의 4대 성질

안전한 트랜잭션을 보장하기 위해 반드시 지켜야 할 4가지 특징입니다.

1. **Atomicity (원자성):**
    - 트랜잭션은 더 이상 쪼갤 수 없는 최소 단위여야 합니다.
    - 작업 전체가 성공하거나 실패해야 하며, 일부만 성공하는 것(Partial Success)은 허용되지 않습니다.
2. **Consistency (일관성):**
    - 트랜잭션이 완료된 후에도 데이터베이스는 항상 일관된 상태(정해진 규칙이나 제약 조건 위반 없음)를 유지해야 합니다.
    - 예: '잔액은 0원 이상이어야 한다'는 제약 조건은 트랜잭션 전후로 항상 만족되어야 합니다.
3. **Isolation (격리성):**
    - 여러 트랜잭션이 동시에 실행되더라도 서로의 작업에 영향을 주거나 끼어들 수 없습니다.
    - 마치 각 트랜잭션이 혼자 시스템을 쓰는 것처럼 격리되어야 합니다.
4. **Durability (지속성):**
    - 성공적으로 커밋된 트랜잭션의 결과는 시스템 장애(전원 꺼짐 등)가 발생하더라도 영구적으로 보존되어야 합니다.
    

## 4. 동시성 제어와 DB Lock (심화)

격리성(Isolation)을 실제로 구현하기 위해 데이터베이스는 **Lock(잠금)** 기법을 사용합니다.

- **배경 (Dirty Read 문제):**
    - 트랜잭션 A가 수정 중인(아직 커밋 안 된) 데이터를 트랜잭션 B가 읽어가는 현상을 방지해야 합니다. 만약 A가 롤백되면 B는 존재하지 않는 데이터를 가진 셈이 되기 때문입니다.
- **변경(Write) 시 Lock:**
    - 데이터를 수정(`Update`)하려는 세션은 해당 데이터의 락을 먼저 획득해야 합니다.
    - 락을 얻지 못한 다른 세션은 락이 반납(Commit/Rollback)될 때까지 **대기(Wait)** 상태가 됩니다.
    - **Lock Timeout:** 무한 대기를 방지하기 위해 대기 시간을 설정하며, 시간 초과 시 에러를 발생시킵니다 .
- **조회(Read) 시 Lock (`select for update`):**
    - 일반적인 조회(`Select`)는 락을 사용하지 않습니다(Non-blocking).
    - 하지만, 조회한 데이터를 바탕으로 중요한 계산을 수행하는 동안 값이 변하면 안 되는 경우, `select ... for update` 구문을 사용하여 조회 시점부터 강제로 배타적 락을 걸 수 있습니다 .
