`#6`

프로그래밍 패러다임은 한마디로 프로그램을 설계하고 구현하는 사고방식과 철학입니다.

개발자분들은 아시겠지만, 코드의 생산성을 높이기 위해선 좋은 설계를 유지하는 것은 필수적인데요.

좋은 설계를 유지한다라는 건, 코드 전반에 걸쳐 일관적인 원칙과 규칙으로 작성이 되어야 한다는 것이고, 이러한 원칙과 방법이 되는 관점을 ‘프로그래밍 패러다임’이라고 부른다고 이해하시면 좋겠습니다.

`#7`

프로그래밍 패러다임은 그림처럼 크게 두 가지 축으로 나뉩니다.

첫 번째는 선언형 프로그래밍, 두 번째는 명령형 프로그래밍이에요.

선언형은 ‘무엇을(What)’ 풀어내는가에 초점을 맞추고, 명령형은 ‘어떻게(How) 할 것인가’에 초점을 둡니다.

그리고 선언형 안에는 함수형 프로그래밍, 명령형 안에는 절차지향과 객체지향이 포함됩니다.

---

`#8`

우선 선언형부터 설명을 드리겠습니다.

선언형은 What 키워드, 즉 무엇을 할지를 표현하고, 그걸 어떻게 할지(How)는 컴퓨터나 함수에게 맡긴다는 사고방식인데요.

---

`#9-1`

예를 들어, 배열에 들어 있는 모든 원소의 값을 2배로 만드는 작업을 해보고 싶다고 해볼게요.

명령형 코드와 비교하며 설명하면 이해가 더 잘 되실 것 같은데요. 먼저 명령형 코드부터 보여드리겠습니다.

⬇️ 명령형 코드

```jsx
let numbers = [1, 2, 3, 4, 5];
let result = [];

for (let i = 0; i < numbers.length; i++) {
  result.push(numbers[i] * 2);
}
```

numbers라는 배열에 있는 원소 5개 1, 2, 3, 4, 5가 보이시죠?

제가 파란 테두리를 한 부분을 보시면, “배열의 인덱스, 즉 i = 0으로 두고 1씩 증가해가면서, 배열의 첫번째 원소 1부터 마지막 원소 5까지 반복하며 각각 2를 곱해라”라는 작업을 이 for문이라는 반복문을 통해 명시하고 있습니다. 즉, 어떻게 (How)를 일일이 설명하고 있죠.

---

`#9-2`

반면 선언형 코드는 어떻게 될까요?

⬇️ 선언형 코드

```jsx
let numbers = [1, 2, 3, 4, 5];
let result = numbers.map(x => x * 2);
```

이 코드에서도 마찬가지로 1, 2, 3, 4, 5 원소가 들어있는 numbers 배열을 선언하지만,

제가 파란 테두리로 강조한 부분을 보시면, 사용자가 로직을 일일이 쓰는 게 아니라, 제가 표시한 이 map함수에게 이 “numbers 배열의 모든 원소에 2를 곱한 새로운 배열을 만들어줘”라고 부탁한 것과 같습니다.

즉, 이렇게 의도만 표현하고 방법은 컴퓨터나 함수에게 맡기는 방식이 선언형 패러다임입니다.

---

`#10` 

함수형 프로그래밍은 바로 이 선언형 패러다임의 대표적인 형태인데요.

선언형은 **“무엇을 할지”에 집중**한다고 말씀드렸죠?

그걸 제대로 하려면, 함수가 **밖에 있는 값이나 상태에 영향을 받지 않아야 해요.**

왜냐하면 밖의 값이 바뀔 때마다 함수의 결과도 바뀐다면,

“이 함수를 쓰면 어떤 결과가 나올까?”를 예측하기 어려워지기 때문이에요.

그래서 함수형은 프로그램의 상태를 바꾸지 않는 ‘순수 함수’와 고차함수로 선언적 스타일의 프로그램을 구현할 수 있는 패러다임입니다.

---

`#11`

그렇다면 순수함수란 무엇일까요?

같은 입력을 주면 항상 같은 결과를 내고, 함수 밖의 상태를 바꾸지 않는 함수를 말합니다.

즉 “이 입력으로 이런 결과를 얻겠다”는 선언에 집중한 것인데요.

```jsx
const pure = (a, b) => {
  return a + b;
};
```

이 코드를 보시면, pure라는 함수가 매개변수로 a와 b를 받아 그 둘을 더한 값을 반환해주고 있는데요. 

같은 입력 `(2, 3)`을 받으면 언제나 결과는 `5` 이기 때문에 이 함수의 결과가 항상 예측이 가능하겠죠? 

그리고 외부에 그 어떤 것도 건드리지 않고 오로지 들어오는 매개변수 a, b에만 영향을 받습니다.

---

`#12`

반면에 이 함수가 외부의 상태를 바꾸게 되면 ‘비순수함수’가 됩니다.

```jsx
let total = 0;
const impure = (a, b) => {
  total += a + b;
  return total;
};
```

현재 이 파란 테두리로 표시해둔 impure 함수 외부에 total이라는 변수가 선언되어 있는데요.

impure 함수 안에서는 입력으로 받은 a와 b를 더한 뒤, 그 값을 total에 더해 다시 저장하고 있습니다.

즉, 함수 **바깥에 있는 변수 total의 값을 직접 변경하고 있는 것**이죠.

따라서 같은 입력 (2, 3)을 주더라도, 함수를 실행할 때마다 누적된 total 값이 달라지기 때문에 결과도 달라집니다.

이렇게 함수가 외부 상태에 의존하거나 영향을 미치는 것을 **‘부수 효과(Side Effect)’**라고 부르며,

이러한 부수 효과를 없애는 것이 함수형 프로그래밍의 핵심입니다.

---

`#13`

앞서 말씀드린 것처럼, 함수형 프로그래밍은 ‘순수 함수’와 ‘고차 함수’를 중심으로 구현되는 패러다임입니다.

순수 함수는 이제 익숙하실 텐데요. 그렇다면 이번엔 ‘고차 함수’가 무엇인지 살펴보겠습니다.

고차 함수란 함수를 값처럼 다루는 함수를 말합니다.

즉, 함수가 단순히 실행되는 대상이 아니라,

다른 함수의 인자로 전달되거나 함수의 반환값으로 사용될 수도 있는 함수를 의미합니다.

이런 동작이 가능하려면, 함수 자체가 ‘일급 객체(First-class Object)’로 취급되어야 합니다.

즉, 숫자나 문자열처럼 함수를 변수에 담거나 전달하거나 반환할 수 있는 ‘값’으로 다룰 수 있어야 한다는 뜻입니다.

---

`#14`

일급 객체의 특징은 다음과 같습니다.

첫째, 변수나 메서드에 값을 할당하듯이 함수를 할당할 수 있습니다.

```jsx
// 함수도 값처럼 변수에 저장
const sayHello = function() {
  console.log("Hello!");
}

// 변수 이름으로 호출 가능
sayHello(); // Hello!
```

sayHello라는 변수에 함수를 할당하고, 아래에서 그 변수 이름 sayHello 으로 함수를 호출합니다.

---

`#15`

둘째, 함수 안에 함수를 매개변수로 담을 수 있습니다.

```jsx
function greet(func) {   // 함수(func)를 매개변수로 받음
  console.log("인사 시작");
  func();                // 전달받은 함수 실행
  console.log("인사 끝");
}

function sayHi() {
  console.log("안녕!");
}

// 함수 자체를 인자로 전달
greet(sayHi);
```

이 코드를 보시면 `greet` 함수와 `sayHi` 함수, 두 개의 함수가 있습니다.

아래에서 `greet` 함수를 호출할 때, **`sayHi` 함수 자체를 인자로 전달**하고 있죠.

즉, `greet` 함수는 전달받은 `sayHi` 함수를 **매개변수 `func`로 받아**, 그 내부에서 `func()`를 실행하는 구조입니다.

이처럼 **함수를 인자로 전달받아 내부에서 실행하는 함수**가 바로 **고차 함수**의 대표적인 형태입니다.

---

`#16`

셋째, 함수가 함수를 반환할 수 있습니다.

```jsx
function makeAdder(x) {
  // 내부에서 새 함수를 만들어 반환 
  return function(y) {
    return x + y;
  }
}

const add5 = makeAdder(5);  // x가 5로 고정된 함수 생성
console.log(add5(3));       // 8
console.log(add5(10));      // 15
```

여기서 `makeAdder` 함수는 **새로운 함수를 만들어 반환하는 고차 함수**입니다.

`makeAdder(5)`처럼 호출하면, 이 인자로 전달된 값 `x`, 즉 5를 **기억하는** 제가 파란 테두리로 표시해둔 이 **내부 함수**가 반환됩니다.

그래서 `add5(3)`을 실행하면 `5 + 3 = 8`, `add5(10)`을 실행하면 `5 + 10 = 15`가 되는 것이죠.

이처럼 **외부 함수의 값을 기억한 채로 동작하는 내부 함수**를 **클로저(Closure)** 라고 부르기도 합니다.

---

`#17`

그래서, 함수형 프로그래밍을 요약하자면,

항상 같은 입력에 같은 결과를 내는 작은 순수함수들을 레고 블록처럼 조립해서 로직을 만드는 게 함수형 프로그램의 핵심이라고 할 수 있고,

고차함수는 이런 블록들을 더 유연하게 다루게 해주는 도구라고 이해할 수 있겠습니다.

---

`#18`

다음은 명령형 프로그래밍입니다.

앞서 설명드린 선언형과 달리, 어떻게(How) 문제를 해결할지 직접 지시하는 방식인데요. 즉, 컴퓨터에게 “무엇을 먼저 하고, 그 다음엔 뭘 할지”를 순서대로 명령하는 겁니다.

---

`#19`

```jsx
let numbers = [1, 2, 3, 4, 5];
let result = [];

for (let i = 0; i < numbers.length; i++) {
  result.push(numbers[i] * 2);
}
```

아까 선언형 패러다임과 비교하면서 보여드린 코드인데요.

이를 바탕으로 명령형 프로그래밍의 특징을 설명드리자면,

프로그램의 흐름, 즉 제어 구조나 반복, 조건 등을 직접 명시한다는 점,

변수의 값이 실행 과정 중에 계속 변하는 것,

사람이 이 코드가 “어떻게 동작하는지” 단계별로 명확히 알 수 있다는 점입니다.

절차지향과 객체지향 패러다임은 이 명령형 패러다임 안에 포함됩니다.

---

`#20`

절차지향은  명령형 프로그래밍의 한 형태로, ‘순서대로 처리하는 절차 중심’의 사고방식입니다.

하나의 프로그램을 여러 개의 작업 단계(절차)로 나누고, 각 단계에서 무슨 일을 할지 구체적으로 지시하는 방식이죠.

---

`#21`

예를 들어 “라면 끓이기”를 코드로 짠다면,

```jsx
function boilWater() {
  console.log("물을 끓인다");
}
function addNoodles() {
  console.log("면을 넣는다");
}
function addSoup() {
  console.log("스프를 넣는다");
}
function eat() {
  console.log("라면을 먹는다");
}

boilWater();
addNoodles();
addSoup();
eat();
```

위에는 물을 끓이는 함수, 면을 넣는 함수, 스프를 넣는 함수, 그리고 먹는 함수가 각각 선언되어 있고,

아래에서는 **이 함수들을 위에서 아래로 순서대로 호출**하고 있습니다.

즉, 이렇게 **차례차례 절차대로 실행되는 구조가 바로 절차지향 프로그래밍의 기본 형태입니다.**

---

`#22`

이러한 절차형 프로그래밍의 특징은,

프로그램이 “무엇을 할까”보다 “어떤 순서로 할까”에 초점을 둔다는 점,

함수(절차) 단위로 나눠서 코드의 재사용이 가능하다는 점,

코드의 흐름이 명확하지만, 데이터와 함수가 따로 존재하므로 데이터의 수정이 일어나면 관련 함수를 모두 수정해야하는 등 관리가 어려워진다는 단점이 있습니다.

---

`#23`

마지막으로 객체지향 프로그래밍은 명령형의 발전된 형태라고 볼 수 있는데요.

데이터(속성)와 그 데이터를 처리하는 메서드(기능)를 하나의 객체로 묶어, 각각의 객체 하나하나가 자신의 데이터와 행동을 함께 가지고 일을 처리하도록 설계하는 방식입니다.

절차지향이 “무엇을 먼저 할까?”에 집중했다면, 객체지향은 “**누가 그 일을 할까?**”에 초점을 둡니다.

---

`#24`

예시 코드로 자동차 시뮬레이션을 만든다면,

```jsx
class Car {
  startEngine() {
    console.log("엔진 시동!");
  }
  pressAccelerator() {
    console.log("부릉부릉~ 속도 증가!");
  }
  brake() {
    console.log("멈췄습니다.");
  }
}

const myCar = new Car();
myCar.startEngine();
myCar.pressAccelerator();
myCar.brake();
```

여기서 Car라는 클래스는 ‘자동차’의 설계도로서 안에 시동을 켜는 행동, 엑셀을 밟는 행동, 브레이크를 밟는 행동들을 모아두고 있고요.

myCar라는 객체는 그 설계도로 만든 실제 자동차 한대입니다.

그래서 myCar는 스스로 엔진을 켜고, 달리고, 멈추는 것처럼 스스로 일을 하는 주체로 표현됩니다.
