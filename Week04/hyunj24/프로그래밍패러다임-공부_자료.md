## 0. 패러다임이란?

- 어떤 한 시대 사람들의 견해나 사고를 근본적으로 규정하고 있는 테두리로서의 인식의 체계, 또는 사물에 대한 이론적인 틀이나 체계를 의미

  ⇒ 쉽게 말해, 어떤 사물을 바라보는 사고의 틀이나 체계

- 대표적인 패러다임의 예로, '천동설'과 '지동설’이 있음.
    - 천문학을 이해하고 바라보는 관점을 천동설은 '지구가 중심이다'라는 관점을 제시한 것이고, 지동설은 '태양이 중심이다'라는 관점을 제시

이러한 패러다임이 프로그래밍 분야에도 적용될 수 있음.

즉, 어떻게 프로그래밍할 것인지에 대한 인식의 체계를 제공해주는 것.

## 1. 프로그래밍 패러다임이란?

- 프로그램을 설계하고 구현하는 사고방식과 철학.
- 프로그래머에게 프로그래밍의 관점을 갖게 해주는 개발 방법론.
- 코드의 생산성을 높이기 위해선, 좋은 설계를 유지하는 것은 필수적이다.
    
    좋은 설계를 유지한다라는 건, 코드 전반에 걸쳐 일관적인 원칙과 규칙으로 작성이 되어야 한다는 것이고, 이러한 원칙과 방법이 되는 관점을 ‘프로그래밍 패러다임’이라고 부른다.
    
- 예시:
    - 객체지향 프로그래밍: 프로그래머들이 프로그램을 서로 상호 작용하는 객체들의 집합으로 볼 수 있게 한다.
    - 함수형 프로그래밍: 상태 값을 지니지 않는 함수 값들의 연속으로 생각할 수 있게 한다.

## 2. 프로그래밍 패러다임의 분류

크게 선언형, 명령형으로 나뉘는데,

선언형은 함수형이라는 하위 집합을 갖는다. 명령형은 다시 객체지향, 절차지향으로 나눈다.


- **선언형(declarative programming)**
    - **‘무엇을(WHAT)’ 풀어내는가에 집중하는 패러다임**
    - “프로그램은 함수로 이루어진 것이다.” 라는 명제가 담겨 있는 패러다임
    - 함수형 프로그래밍은 선언형 패러다임의 일종
- **명령형(Imperative programming)**
    - **‘어떻게(HOW)' 풀어가는가에 집중하는 패러다임**
    - 컴퓨터가 수행할 명령들을 순서대로 적어두는 프로그래밍 수행 기법

## 3. 선언형 프로그래밍이란?

> “무엇을 할지(What)를 표현하고, 그걸 어떻게 할지(How)는 컴퓨터나 함수에게 맡긴다”는 사고방식
> 

명령형과 비교 ⬇️

- **명령형(Imperative)**
    
    : “어떻게 할지”를 일일이 지시하는 방식
    
    ```jsx
    let numbers = [1, 2, 3, 4, 5];
    let result = [];
    
    for (let i = 0; i < numbers.length; i++) {
      result.push(numbers[i] * 2);
    }
    
    console.log(result); // [2, 4, 6, 8, 10]
    ```
    
    “i를 0부터 시작해서, 배열 끝까지 반복하고, 각 원소에 2를 곱해서 result에 넣어라”
    
    **→ 절차(How)에 집중한 코드**
    

- **선언형(Declarative)**
    
    : “무엇을 하고 싶은지”만 말하는 방식
    
    ```jsx
    let numbers = [1, 2, 3, 4, 5];
    let result = numbers.map(x => x * 2);
    console.log(result); // [2, 4, 6, 8, 10]
    ```
    
    “배열의 모든 원소에 2를 곱한 새로운 배열을 만들어줘”
    
    **→ 목적(What)에 집중한 코드**
    

## 4. 함수형 프로그래밍

선언형 방식을 **순수함수와 고차함수로 구현하는 패러다임**

선언형 프로그래밍이 “**무엇을 할지**”에 집중하려면, 함수가 외부 상태에 의존하지 않아야 한다.

왜냐하면 외부 상태가 바뀌면 “무엇을 할지”가 매번 달라져서 예측하기 어려워지기 때문이다.

### 순수함수란?

> “입력 → 출력”만으로 완결된 계산
> 

> 즉, “이 입력으로 이런 결과를 얻겠다”는 선언에 집중
> 

예시 코드

```jsx
const pure = (a, b) => {
	return a + b
}

console.log(pure(2, 3)) // 항상 5
console.log(pure(2, 3)) // 여전히 5 (예측 가능)
```

→ 같은 입력`(a, b)`이면 항상 같은 출력을 내고, 외부 상태 변경 없음.

→ 들어오는 매개변수 a, b에만 영향을 받음

그럼 비순수함수는?

```jsx
let total = 0;

const impure = (a, b) => {
  **total = total + a + b;  // 외부 변수 total 변경**
  return total;
}

console.log(impure(2, 3)); // 5
console.log(impure(2, 3)); // 10 ← 외부 상태(total)가 바뀜
```

→ 문제점: 함수가 외부의 `total`을 바꿔버림.

**같은 입력 `(2, 3)`이라도 호출할 때마다 결과가 달라짐.**

⇒ 이러한 외부 변수가 변경되는 것을 ‘부수 효과(사이드 이펙트)’라고 함.

```jsx
let randomOffset = Math.random();  // 외부 상태 (랜덤)

const impure = (a, b) => {
  **return a + b + randomOffset; // 외부 값에 의존** 
}

console.log(impure(2, 3)); // 예: 5.72
console.log(impure(2, 3)); // 예: 5.13
```

→ 문제점: 함수 내부 로직이 외부의 랜덤 상태에 의존.

**입력이 같아도 결과가 달라지므로 예측 불가능.**

### 고차함수란?

함수가 함수를 값처럼 매개변수로 받아 로직을 생성할 수 있는 것을 말한다.

**일급 객체**

고차 함수를 쓰기 위해서는 해당 언어에서 함수가 일급 객체로 취급되어야 한다.

⇒ 즉, **함수가 숫자나 문자열처럼 값(value)으로 다뤄질 수 있어야** 한다는 말이다.

일급 객체의 특징은 다음과 같다.

- 변수나 메서드에 함수를 할당할 수 있다.
    
    ```jsx
    // 함수도 값처럼 변수에 저장
    const sayHello = function() {
      console.log("Hello!");
    }
    
    // 변수 이름으로 호출 가능
    sayHello(); // Hello!
    ```
    
    → **함수가 값처럼 변수에 담긴다**는 건, 정수나 문자열을 변수에 저장하듯 함수도 "데이터"로 다룰 수 있다는 뜻이다.
    
- 함수 안에 함수를 매개변수로 담을 수 있다.
    
    ```jsx
    function greet(func) {   // 함수(func)를 매개변수로 받음
      console.log("인사 시작");
      func();                // 전달받은 함수 실행
      console.log("인사 끝");
    }
    
    function sayHi() {
      console.log("안녕!");
    }
    
    // 함수 자체를 인자로 전달
    greet(sayHi);
    ```
    
    출력 결과:
    
    ```jsx
    인사 시작
    안녕!
    인사 끝
    ```
    
    → `greet`는 다른 함수를 매개변수로 받아서 내부 로직에 사용하는 전형적인 고차함수이다.
    
- 함수가 함수를 반환할 수 있다. (함수를 만들어서 돌려줌)
    
    ```jsx
    function makeAdder(x) {
      // 내부에서 새 함수를 만들어 반환 
      return function(y) {
        return x + y;
      }
    }
    
    const add5 = makeAdder(5);  // x가 5로 고정된 함수 생성
    console.log(add5(3));       // 8
    console.log(add5(10));      // 15
    ```
    
    → 여기서 `makeAdder`는 **함수를 반환하는 함수**, 즉 **고차함수**
    

**정리**

함수형 프로그래밍은 **“함수를 레고 블록처럼”** 생각하는 방식이다.

- 순수 함수는 항상 같은 입력에 같은 결과를 내기 때문에, 다른 코드에 영향 주지 않고 마음 놓고 조립할 수 있는 블록이라고 보면 됨.
    
    → 예를 들어, `더하기 블록`, `곱하기 블록`, `필터링 블록` 같은 셈
    
- 이렇게 작고 믿을 수 있는 블록(순수 함수) 들을 필요한 순서대로 조립해서 하나의 로직을 만든다는 게 함수형 프로그래밍의 핵심이다.
    - 즉, 복잡한 과정을 한 번에 짜는 게 아니라 "입력 → 변환 → 결과" 과정을 여러 개의 함수로 나눠서 연결하는 것이다.
- 그리고 고차 함수는 이런 블록들을 더 유연하게 다루게 해주는 도구이다.
    
    함수 자체를 입력으로 받거나, 새로운 함수를 만들어서 반환할 수 있기 때문.
    
    → 예를 들어 “이 리스트의 모든 값을 2배로 만들어줘” 같은 일을 할 때, `map()`이라는 고차 함수에 “2배로 만드는 함수”를 넘겨주면 끝이다.
    

## 5. 명령형 프로그래밍이란?

> “어떻게(HOW) 문제를 해결할 것인가”에 집중하는 프로그래밍 방식
> 

명령형 프로그래밍(Imperative Programming)은 컴퓨터에게 **명령(Instruction)** 을 순서대로 내리는 형태의 프로그래밍이다.

즉, “무엇을 할지(What)”보다는 **“어떤 절차로 할지(How)”** 를 구체적으로 지시한다.

예시 코드 (위에 선언형 설명에서 제시되었던 코드)

```jsx
let numbers = [1, 2, 3, 4, 5];
let result = [];

for (let i = 0; i < numbers.length; i++) {
  result.push(numbers[i] * 2);
}

console.log(result); // [2, 4, 6, 8, 10]
```

⇒ 프로그램이 동작하는 **순서와 절차**가 코드에 그대로 드러나는 것이 특징

**명령형 프로그래밍의 특징**

- 프로그램의 흐름(제어 구조, 반복, 조건 등)을 직접 명시한다.
- 변수의 값이 실행 과정 중에 계속 변한다(상태 변화).
- 사람이 “어떻게 동작하는지”를 단계별로 명확히 알 수 있다.

## 6. 절차지향 프로그래밍

> 명령형 프로그래밍의 한 형태로, 프로그램을 ‘절차(Procedure)’ 단위로 구성하는 방식
> 

절차지향 프로그래밍은 **‘순서(절차)’ 중심의 사고방식**이다.

하나의 프로그램을 여러 개의 **작업 단계(절차)**로 나누고, 각 단계에서 무슨 일을 할지 **구체적으로 지시**하는 방식.

[예시 코드]

예를 들어 “라면 끓이기”를 코드로 짜면 ⬇️

```jsx
function boilWater() {
  console.log("물을 끓인다");
}
function addNoodles() {
  console.log("면을 넣는다");
}
function addSoup() {
  console.log("스프를 넣는다");
}
function eat() {
  console.log("라면을 먹는다");
}

boilWater();
addNoodles();
addSoup();
eat();
```

위에서 아래로 순서대로 실행된다.

각 함수가 “절차(Procedure)”에 해당하고, 프로그램 전체는 이런 절차의 흐름으로 구성된다.

**특징**

- 프로그램이 “무엇을 할까”보다 “어떤 순서로 할까”에 초점을 둠
- 함수(절차) 단위로 나눠서 코드의 재사용은 가능
- 하지만 **데이터와 함수가 분리되어** 있어서, 데이터 구조가 바뀌면 관련 함수들을 전부 고쳐야 하는 단점이 있음

## 7. 객체지향 프로그래밍

> 명령형 프로그래밍의 또 다른 형태로,
> 
> 
> **데이터(속성)와 그 데이터를 처리하는 메서드(기능)를 하나의 객체로 묶어** 설계하는 방식이다.
> 

객체지향은 **현실 세계의 개념을 프로그램 안으로 옮겨오는 사고방식**이다.

즉, 현실의 “사람”, “자동차”, “학생” 같은 개념을 각각의 객체(Object)로 표현하고이 객체들이 서로 상호작용하게 만든다.

절차지향이 “무엇을 먼저, 다음에 할까?”라면, 객체지향은 “**누가 그 일을 할까?**”를 생각한다.

[예시 코드]

자동차 시뮬레이션을 만든다면 ⬇️

```jsx
class Car {
  startEngine() {
    console.log("엔진 시동!");
  }
  pressAccelerator() {
    console.log("부릉부릉~ 속도 증가!");
  }
  brake() {
    console.log("멈췄습니다.");
  }
}

const myCar = new Car();
myCar.startEngine();
myCar.pressAccelerator();
myCar.brake();
```

- “자동차(Car)”라는 객체 안에 **행동(메서드)** 들을 모아둠
    - 시동을 켜는 행동
    - 엑셀을 밟는 행동
    - 브레이크를 밟는 행동
- “Car”는 자동차의 설계도, “myCar”는 그 설계도로 만든 실제 자동차 한 대, 메서드들은 그 자동차가 할 수 있는 행동들
- 사람, 자동차, 주문 같은 **‘명사’**들을 프로그램 안의 객체로 보고, 각 객체가 **스스로 행동(동사)**을 할 수 있게 만드는 것이다.
- 즉, **명령어 중심(절차지향)**이 아니라 **‘주체가 스스로 일하는 구조’(객체지향)**로 코드를 짜는 것이다.

**특징**

- **캡슐화 (Encapsulation)** → 관련된 데이터와 기능을 한 객체 안에 묶기
- **상속 (Inheritance)** → 기존 객체를 확장해 새로운 객체 만들기
- **다형성 (Polymorphism)** → 같은 메서드라도 객체에 따라 다르게 작동
- **추상화 (Abstraction)** → 불필요한 세부 내용은 감추고 필요한 기능만 보이게 하기

한줄 요약

<aside>

객체지향 프로그래밍은 **“현실 세계의 사물(객체)”을 코드로 표현해**, 각각이 **스스로 행동하고 협력**하도록 만드는 방식이다.

유지보수와 확장이 쉽고, 코드 재사용성이 높다.

</aside>
